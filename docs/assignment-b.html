Definitions (quick guide)

  • LIFO (Last In, First Out): the most recently added item is removed first. A stack follows LIFO.
  • FIFO (First In, First Out): the earliest added item is removed first. A queue follows FIFO.
  • Binary min-heap: a tree-like structure stored in an array where each parent is less than or equal to its children; removing always returns the smallest element by a chosen rule.
  • Clamp: limit a value to a range. For example, clamping 5.8 to the range [1, 5] gives 5.
  • Round: convert a number to the nearest whole number. For example, 3.49 rounds to 3; 3.50 rounds to 4.
  • OKR: “Objectives and Key Results,” a goal-measure often recorded on a 0–100 scale in this dataset.

Part 1 — Stack (LIFO)

What this means

A stack removes the most recent item first. In this simulation: last hired, first out. The newest hire sits at the top of the stack.

What to do in Lifolayoffs.kt

  • Implement a linked stack with:
    • push(item): place an item on top
    • pop(): remove from top; throw if the stack is empty
    • peek(): read the top item, or null if empty
    • isEmpty() and size()

How it runs

Load the CSV, sort by hireDate (earliest to latest), push in that order so the newest hire ends up on top, then repeatedly pop to produce the layoff order.

Be careful: pop() on an empty stack must throw; peek() must not change the size.

Part 2 — Linked Queue (FIFO)

What this means

A queue removes the earliest item first. In this simulation: first hired, first out. The earliest hire sits at the head of the queue.

What to do in LinkedQueue.kt

  • Implement a linked queue with a head and a tail:
    • enqueue(x): add to tail
    • dequeue(): remove from head; throw if the queue is empty
    • peek(): head value, or null if empty
    • isEmpty() and size()

How it runs

Load the CSV, sort by hireDate (earliest to latest), enqueue in that order, then repeatedly dequeue to produce the layoff order (earliest first).

Be careful: when removing the last item, set both head and tail to null. Keep size correct at all times.

Part 3 — Performance score (returns 1..5 or null)

Why we need it

The priority policy needs one number per person. The recipe below is fixed and small. If there is not enough information, return null.

Step 1: Reviews (R)

Use any values that are present; ignore missing or NaN:

  • selfEvaluation (1–5)
  • peer360Feedback (1–5)
  • managerFeedback (1–5)
  • okr / 20.0 (convert OKR 0–100 to a 0–5 scale)

R is the average of the present review values. If none are present, R is null.

Step 2: Behavior (B)

  • Productivity = problemsFixed / problemsAssigned (if problemsAssigned is 0, skip productivity)
  • Punctuality = punctualityRate in the range 0..1

Map any behavior value v in the range 0..1 to the 1..5 scale using 1 + 4*v. If you have one or two mapped behavior values, B is the average. If none, B is null.

Step 3: Combine and finish

  • If both R and B exist: raw = 0.7*R + 0.3*B
  • If only R exists: raw = R
  • If only B exists: raw = B
  • If neither exists: return null

Then clamp raw to the range 1.0..5.0, round to the nearest whole number, and return that integer.

Common mistakes to avoid: do not treat missing values as 0; just ignore them. Do not include productivity when problemsAssigned is 0. Always divide OKR by 20 before averaging with 1–5 ratings. Always clamp to 1..5 and round to an integer at the end.

Your task in Performance.kt: implement computePerformanceScore(e: Employee): Int? exactly as described above.

Part 4 — Priority layoffs (min-heap)

What this means

A min-heap removes the smallest item first, based on a rule. Here, the rule uses two keys. The first key is performance; the second key is cost. Smaller comes out earlier.

Policy (two keys, in this order)

  1. Lower performance first. People with a real score 1..5 are considered before people with a null score.
  2. Higher cost next. Among equal performance, a higher positive costToCompany comes out earlier. Zero or missing cost should not move someone earlier.

Implementation idea

perfKey = performanceScore ?: Int.MAX_VALUE
costKey = if (costToCompany > 0) -costToCompany else Int.MAX_VALUE
// Compare (perfKey, costKey) lexicographically in the min-heap.
// Exact ties can be left as-is.

What to do in PriorityQueue.kt

  • Build a small MinHeap<T> with push, pop, peek, isEmpty, size, and correct siftUp/siftDown.
  • Write sortEmployeesByPriority(...) to:
    • compute performance scores (Part 3),
    • push everyone into the heap using the policy above,
    • pop repeatedly to get the layoff order.
Be careful: treat null performance as worst (after real scores). For the same performance, higher positive cost comes first; zero or missing cost is last in that tie. In siftDown, always compare to the smaller child because this is a min-heap.
